# 需求澄清（Requirement Clarify）

本技能是 **前置流程的第一步**：通过交互式对话澄清用户提供的粗略需求，明确具体要求、识别优化方向，为后续「生成 newneed.md」和「分解任务」做准备。

## 触发场景

- "澄清这个需求"、"帮我明确这个需求"、"这个需求需要什么"
- 流程编排指示「前置步骤 1：需求澄清」时
- 用户提供粗略或不完整的需求描述

## 输入

- **粗略需求描述**：用户提供的自然语言需求（如"构建一个 TypeScript CLI todo 应用"）

## 必做动作

1. **分析初始需求**：
   - 识别需求类型（Web 应用、CLI 工具、API、库、修复任务等）
   - 提取关键功能点
   - 识别技术栈线索

2. **主动澄清关键问题**：
   - **技术栈**：使用的编程语言、框架、库
   - **功能范围**：核心功能 vs 可选功能
   - **约束条件**：性能要求、兼容性、安全要求
   - **用户场景**：目标用户、使用环境
   - **数据存储**：是否需要持久化、数据格式

3. **识别优化方向**（可选）：
   - 性能优化、用户体验、代码质量、安全性、可维护性、可扩展性等
   - 询问用户是否将这些优化项纳入后续任务

4. **输出澄清后的需求**：
   - 将澄清后的需求以结构化形式输出（技术栈、功能范围、约束、场景等）
   - 供下一步 **requirement-to-newneed** 使用

## 与脚本的关系

- `requirement-workflow.sh` 在非 `--decomposed` 模式下会调用分解脚本，但分解脚本通常需要较清晰的需求输入。
- 本技能供「按步调用技能」的前置流程使用：在用户提供粗略需求后、**requirement-to-newneed** 之前调用。

## 相关技能

- **requirement-clarifier**：更完整的需求澄清与任务生成流程（含优化识别、任务格式生成）。
- **requirement-to-newneed**：下一步，将澄清后的需求写入 newneed.md。

## 完成标准

- 已通过对话明确用户的具体要求（技术栈、范围、约束、场景）。
- 澄清后的需求已输出，可进入下一步「生成 newneed.md」。
