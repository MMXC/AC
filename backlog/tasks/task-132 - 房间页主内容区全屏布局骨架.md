# Task: 房间页主内容区全屏布局骨架

## Description

将 join.html 从「左侧边栏 + 右侧内容区」改为内容为主的布局骨架：主内容区（共享 iframe/视频）全屏或近全屏占据可视区域；左侧房间信息、成员列表、聊天改为可收起/浮层或移除固定占位，不再长期占用主区域宽度。先完成布局与主内容区占位，不要求 overlay 控件样式。

**测试用例**:

**测试场景**:
1. 房主或成员打开 join.html 进入房间，确认主内容区（iframe 区域）为视觉主体
2. 确认左侧无固定宽侧栏长期遮挡主内容

## Success Criteria

- [x] #1 主内容区（.browser-area / iframe 容器）在桌面视口下占据除必要边距外的主要可视区域（如 ≥80% 宽度或全宽）
- [x] #2 原左侧边栏不再以固定宽度长期占据左侧，改为可收起、浮层或底部/侧边抽屉入口
- [x] #3 页面仍能正常加载房间、展示共享 iframe 与现有功能入口（可暂用临时入口进入成员/聊天）

## Implementation Steps

1. **1.1 主内容区全宽骨架** — 桌面视口下 `.browser-area`（含 iframe 容器）占据除必要边距外的主要区域（≥80% 宽度或全宽）；验收：桌面宽度下 .browser-area 计算宽度 ≥ 80vw 或等同剩余空间。
2. **1.2 左侧边栏改为可收起/浮层** — 原 `.sidebar` 不再以固定宽度占据左侧；改为默认隐藏或折叠，通过入口（如头部按钮）打开为浮层或侧边抽屉；验收：默认状态下主内容区全宽，无固定宽侧栏占位；存在可打开侧栏的入口。
3. **1.3 功能与入口保留** — 房间加载、共享 iframe、成员列表、聊天等仍可用；侧栏打开后内容与原有一致；验收：join.html 正常加载房间、展示 iframe，侧栏内房间信息/成员/聊天可访问（可暂用临时入口进入）。
